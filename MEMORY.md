# Stable Saathi decisions

- Human supplied a Meta Model API dashboard and requested inexpensive/selectable inference. OpenRouter remains free-only by default; cheap models use a separate token-rate opt-in. Meta has its own key/opt-in and Standard-mode text allowlist; credits/billing are unverified. Contributor-mode training consent is not inferred from lower-cost requests. Model switching cannot replay a run.

- Human chose fully self-hosted threads and memories. The initial local entry uses server-side SQLite with browser-scoped anonymous workspaces and explicitly reviewed preferences; no Intelligence service/key is required. Model inference may still use OpenRouter, so context sent for an answer leaves the server. Upstream worker/computer/full-UI integration remains a separate migration; no fake cloud entitlement or in-memory-only durability substitute.

- This fork uses OpenDuet/OpenBot/CopilotKit as a candidate product foundation. The Python Saathi reference and deployed Home Agents site remain separate; no data/runtime migration has happened.
- First priority is everyday tasks and the dental appointment vertical. Kitchen and inventory are separate specializations. Text-language instructions are not measured Indic speech capability.
- Initial inference profile uses OpenRouter free models; models remain replaceable. No paid fallback is configured. Key guardrails must control spend even if upstream UI settings change.
- The separate full upstream entry still requires CopilotKit Intelligence for its threads/runners. The self-hosted starter does not use that service. Optional telemetry opt-out alone is not a replacement for cloud storage; the local mode has its own durable store.
- Public WhatsApp, real account actions, purchases/payments and production hosting require their own access, policy, identity and operational decisions. No upstream feature claim proves Saathi-specific readiness.

- Explicit current-information requests can use native Meta read-only search/page opens with the existing key. OpenRouter remains free/text-only and never switches silently. Local SQLite still owns threads/memory; stateless Meta requests use store=false. Source links distinguish search hits, completed page opens and citations; provider evidence is not independent freshness or accuracy proof.

- The human requested missing-PRD development in the active OpenDuet fork. Keep the PRD's workflow requirements with the later self-hosted runtime decisions. The first action path is a controlled SQL demo clinic with explicit user review/approval and MOCK receipts; the chat model cannot authorize bookings. Voice, real providers, reminders and generic task planning remain separate work, not features implied by this simulation.

- Task planning pins credential-free independent role settings at creation and shares the chat inference ledger. A schema-valid proposal is still an unverified draft: it cannot authorize execution, approve a booking or become a receipt. Cancellation suppresses late output, and restart never silently replays an interrupted planner.
