# Next slice: explicit operator media expiry maintenance

Proposed, not implemented/assigned. Preserve the current public/private profiles. Implement against fresh synthetic DBs first; do not execute maintenance on existing user/production data as part of development.

Build a narrowly scoped operator command with a required explicit database path, no dotenv/private-profile defaults, no public/model/anonymous dispatch and no provider call. Default to a count-only dry run; require an explicit apply argument for expired active BLOB/linked-result clearing. Output aggregate counts only. Nonexistent targets, malformed/newer/older schemas and currently-owned databases must fail without creating/migrating a target or changing its data. Schema11 is the current required format; version labels alone must not authorize an incomplete/malformed store.

Important code fact: SelfHostedStore currently creates/migrates tables and interrupts pending STT/plans/chat during construction. A maintenance command must not silently do that merely to inspect or expire media. Reuse/factor the authoritative kernel ownership guard and a strict existing-schema opener; inspect under that ownership before any DDL/journal/permission/data mutation. Keep ordinary application startup/migrations unchanged. Review equivalent file paths/aliases so the maintenance lock cannot bypass a running server's guard. Do not replace the OS lock with PID files or bypass it on failure.

The apply transaction should reuse OwnedMedia.purgeExpired and the existing consent/history/output-invalidation trigger semantics. Clear only expired active BLOBs and their linked retained outcomes; preserve nonexpired media, owner scope, tombstones, consent history, unrelated task/booking/chat state and admission/inference ledgers. No implicit startup recovery, replay, refund, account erasure or logical quota reset. Dry run performs no lifecycle writes. No schema migration or background scheduler guarantee.

Tests first: explicit path/argument errors; missing/legacy/newer/incomplete schema refusal and unchanged version/data; active kernel lock/alias rejection; accurate dry-run count/no data changes; apply/repeat cleanup; consent-history failure rollback; output clearing/pending-worker semantics; preserved nonexpired data and all unrelated ledgers/tasks. Exercise the actual CLI against temporary synthetic files as well as unit boundaries. Run full focused/server/frozen/format/packed gates and checkpoint a feature PR. Logical SQLite clearing does not securely erase backups/WAL or already-returned copies. Runtime admission/shutdown wiring and actual upload/speech remain later gated slices.
