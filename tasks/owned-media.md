# Internal owned-media increments

Start from verified PR19. Keep uploads, routes, vendor registration and public/private migrations disabled. The immediate increment is a pure admission contract, not a media store: accept bounded PCM16 WAV bytes only, separate literal storage consent from optional processing consent, reject URLs/paths/client ownership/expiry fields, copy bytes and derive metadata/digests. Server context supplies the authenticated anonymous owner/session expiry and time; this helper cannot authenticate that context. Retention is at most15 minutes and never exceeds the session. No claim that a valid WAV contains genuine speech.

Next increment after fresh usage: schema-v8 internal SQLite store, fresh synthetic DB only. Proposed bounds: at most10 clips/20MB per owner and100MB global active stored bytes; count expired rows until explicit cleanup actually deletes their blobs. Atomically enforce quotas and UNIQUE(owner,request), return original metadata for exact duplicates, conflict on changed bytes/language/consent, preserve existing v7 state/usage. Never silently extend retention on duplicate.

Every read must verify owner, current consent/revocation and expires>now. Expiry denies new reads; explicit deletion/revocation must remove the active blob and be repeat-safe. SQLite row deletion is logical, not secure erasure of WAL/backups or remote provider copies. No background cleanup guarantee. Cover duplicate/quota/deletion/expiry/restart/concurrent-admission and preservation cases before any route. Decide consent revocation/processing leases and durable speech admission/billing separately before sending stored audio to a provider. Real speech evaluation and public channels remain gated.

Tests for the first admission boundary: missing module red; absent/false storage consent, unknown/client context fields, MIME-only/fake/oversized WAV, invalid/expired context; copied bytes, measured metadata, TTL/session clamp, stable request digest and changed consent/language digest. No provider, database or filesystem writes by the helper.

Durable-store contract for the next slice: SelfHostedStore.media exposes admit(owner,input), metadata(owner,id), read(owner,id), remove(owner,id), revoke(owner,id), revokeProcessing(owner,id) and operator-only purgeExpired(). Owners come from authenticated server context, never a request body. Resolve active session expiry from SQLite; no client timestamp or TTL. Keep terminal tombstones so a duplicate cannot revive deleted/revoked/cleaned content. Add lifetime100-records/owner and5,000-records/global ceilings against tombstone churn; test-only limit overrides may tighten defaults only. Expired blobs still consume quota until explicit removal/cleanup. Reads return copied bytes after ownership/state/expiry/digest checks and do not grant provider processing. Returning bytes before a later revoke cannot be recalled; no processing lease is implemented. Store all data in an additive v8 table using parameterized SQL, immediate admission transactions and the existing kernel-lock discipline. Only fresh synthetic databases may be opened by this development slice.

Trust boundaries: untrusted WAV and request IDs enter strict admission; only server owner/time/session state can set ownership and expiry. Guessing another clip ID must yield404; no metadata/audio leak. Concurrent admissions must obey unique request/aggregate quotas; content changes under the same request ID conflict409. Explicit deletion/revocation clears the active BLOB atomically but keeps minimal idempotency metadata; WAL/backups are not securely erased. No channel route, provider call, scheduling guarantee or permission to migrate live data follows from this schema.
