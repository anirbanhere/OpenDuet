# Fixture STT admission before execution leases

Stack on PR22. First implement only durable STT reservations, not provider execution/claims. Schema10 adds owned admissions and a separate durable admission-unit ledger. Input is request_id/media_id/exact consent_revision; the server supplies the credential-free speech role. Accept reviewed fixture-a/b synthetic-stt-v1 roles only; live/disabled/unimplemented speech cannot be admitted. No routes, provider invocation, raw audio return, lease token or transcript exist in this increment.

Admission atomically verifies active owner/session and current media consent/expiry, pins media hash/revision/hint/duration and the validated fixture role, reserves one slot per owner and charges one admission plus audio milliseconds. Defaults20 global/4 owner admissions per UTC day and300s global/60s owner audio units, with lifetime5,000 global/100 owner records; test overrides tighten only. These are reservation/unit ceilings, not actual inference attempts or verified currency billing. Cancellation does not refund units. Keep the ledger independent of removable task rows so future deletion cannot silently refund daily limits; future account erasure/aggregation remains a separate retention decision.

Exact request duplicates return the original reservation/role with no new charge, even if current default roles change. Changed media/revision under the same request ID conflicts409. No client role, key or grant fields. Partial unique index plus immediate transactions enforce one reserved STT request/owner across connections. Cancellation is repeat-safe and clears only a reservation (no provider is running). Exclusive startup marks leftover reservations interrupted; duplicate requests never replay them. Reserve/cancel are not transcriptions or completed tasks.
