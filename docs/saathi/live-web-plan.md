# Read-only lookup and India date correction

29 October 2026. Human reported that the shared app could neither answer a Chennai forecast nor check the IMD site, and showed an incorrect relative date. Root cause: the deployed adapter explicitly grants no tools and has no trusted clock context. This slice adds public web retrieval to the enabled Meta adapter and fixes date grounding for every provider. No account actions, payments, speech, arbitrary host-side browser code or private data upload is authorized.

Use documented Meta Responses API `web_search`, stateless `store=false`, no conversation/previous-response IDs, one bounded HTTP attempt and at most three built-in read-only tool calls. Ask for raw search results; validate response status, allowed output item types and citation URLs against returned results, source metadata or completed page-open URLs. Sources are provider-reported evidence, not independent truth/freshness proof. The live API accepts only tool_choice=auto (observed HTTP 400 for required); require actual tool evidence in explicit current-weather/site responses; never invent a forecast or claim a page visit based only on model text. Public pages/snippets are untrusted instructions. No model-written code or URLs are fetched by the credential-bearing host.

Local SQLite remains authoritative for messages/memory/run identity. Persist compact source evidence with the saved assistant message and run, so duplicates and reloads retain it without repeating search. New evidence table/schema v4 must migrate existing v1/v2/v3 state without erasure; preserve quota usage. Render safe source anchors using DOM text nodes; no model HTML/Markdown execution. Show retrieval time, provider/capability and scoped limitations. Distinguish citation, search-result and page-open links. An empty-result lookup gets an application-written unverified-information reply; model prose alone cannot prove retrieval.

An injected request clock computes today/tomorrow in Asia/Kolkata, including the UTC/IST midnight boundary. New clock/tool instructions explicitly supersede earlier assistant claims about dates or unavailable browsing. Other providers remain text-only with the same clock; no silent Meta switch or paid OpenRouter fallback. Expose the capability in the model picker and clear unsupported-provider guidance.

Acceptance: clock-boundary regression; provider request/status/tool/citation/URL/budget tests; evidence migration/ownership/duplicate/reopen tests; UI source-link/reload/mobile checks; scoped CI/build/audit; fresh synthetic-only Meta weather + IMD lookup before public update. Back up the retained GCP data disk, update only the existing demo VM release, preserve existing workspaces/quotas and keep legacy Python service unchanged. Record exact observed evidence/failures, not a generalized weather accuracy claim.

Primary sources checked: [Meta search grounding](https://dev.meta.ai/docs/search-grounding), [Responses schema](https://dev.meta.ai/docs/api-reference/responses/schemas), [official IMD Chennai](https://mausam.imd.gov.in/chennai/).
