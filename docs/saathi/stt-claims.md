# Private fixture STT claims and settlement

Schema11 extends the internal admission store with one-shot claims, private-worker settlement and result-retention gates. These primitives invoke no adapter/network provider, start no worker and expose no HTTP/channel route. All development evidence uses fresh synthetic SQLite state and generated tones. They do not prove real ASR quality or enable public speech. Older binaries refuse11; do not launch this branch on an existing profile or deploy without a separately authorized consistent backup/upgrade.

`claim(owner,id,currentServerRole)` runs under the admission write transaction. It rechecks the exact pinned fixture profile and authoritative media consent revision/content hash/expiry, then returns detached audio and a random private executor token exactly once. Only the token hash is stored. Deadline is clamped to role timeout, media expiry and current session expiry. Subsequent claims return owned saved status/outcome, never another audio copy or token. A policy/media failure blocks the reservation without refunding units; it cannot silently switch models or reprocess.

The fresh claim object is frozen; audio/token properties are nonenumerable so ordinary JSON/spread projection omits them. This is an accidental-disclosure guard, not a substitute for a trusted worker boundary. Only the in-process server coordinator may read these fields. Never pass them to a browser, model, WhatsApp message, trace or status/history. No coordinator is wired in this slice.

`settle(owner,id,executorToken,outcome)` authenticates the private capability with a constant-time hash comparison **before** parsing an outcome. It uses the shared fixture validator, bounds encoded retention to20,000 string units and records a canonical digest for exact duplicate/conflict handling. Tokens are scoped to one admission. Completed fixture evidence or a fixed failure code can settle once; changed duplicate input conflicts. A digest/typed outcome is not authentication, a real-world receipt or proof that inference happened.

Cancel before claim releases a reservation. Cancel/revoke after claim retains its pending owner slot until authenticated acknowledgement or exclusive restart. Late cancelled/revoked/expired text is discarded. A result past its claim deadline becomes a fixed timeout failure; no late text is retained. The private worker can acknowledge after user-session expiry to release its slot, but cannot expose/store private output then. User status/claim/cancel still require the existing active owner session. No user authentication flow is changed and no settlement route is public.

Stored results are readable only while original media/session/processing consent revision remain valid. Historical completed state may remain after revocation while its outcome is null; state alone is not fresh content permission. A SQL trigger in the media transaction clears saved output on consent changes, deletion and explicit expiry purge. Trigger/history failure rolls the whole change back. Expiry denies result reads immediately; physical clearing still requires explicit cleanup. Logical SQLite clearing does not securely erase WAL/backups or copies already returned/sent. Minimal digests/lifecycle metadata remain for idempotency; full account erasure/aggregation remains separate work.

Exclusive startup interrupts ambiguous reserved/claimed work, clears pending and in-flight token authority, preserves cancellation/revocation labels and never replays inference. Settled results/duplicates can survive reopen while retention permits. Admission/audio-unit ledgers are unchanged and never refunded; they are not verified currency billing or actual-provider-call counters.

Tests cover genuine v10 migration, private serialization/token scoping, nonce-before-parser authentication, stale/expired/revoked/corrupt media and policy changes, duplicate/conflicting settlement, deadlines/session expiry, output deletion/purge/rollback, reopen/no replay and real separate-process single handoff. Next: a bounded in-process fixture coordinator with cooperative cancellation/deadline signals, then separately gated live-provider policy/setup, supported media routes and actual consented language evaluation. Public voice/WhatsApp and real transactions remain disabled.
