# Keyless fixture STT execution

`FixtureSttCoordinator` connects the internal owned-media/admission/claim/settlement boundaries to the existing keyless synthetic STT registry. It is an in-process server module, not a public audio route or live speech service. Schema remains11. No existing profile has been opened/migrated and no deployment is implied. Do not start a newer store on existing data without the separately backed-up upgrade procedure.

Run `bun run saathi:stt:fixture` from the repository root for a reproducible end-to-end developer demonstration. It ignores private/inherited configuration, creates a fresh temporary SQLite store, generates en/hi/ta tones, admits explicitly consented synthetic media, reserves/claims/executes/settles with both fixture providers, verifies duplicate reuse, stops/drains each coordinator in finally before store close and deletes its temporary state. It accepts no input/path and disables fetch. Output contains aggregate synthetic case status only; no session credential, media bytes or executor token. This command is not ASR/TTS quality evaluation, a natural-language CLI or public consent UI.

Server code constructs the coordinator with `store.sttAdmissions` and a trusted getter for current `config.roles`. `run(owner,id,parentSignal?)` can consume only a pre-existing owned fixture admission. Current role policy is checked at the atomic claim; the invocation uses the pinned fixture provider/model, never another model or a live factory. Default registry implements generated-tone hash lookup, not recognition of recorded speech. Trusted test injection is a code seam, never request/model-controlled adapter configuration.

Only the coordinator reads the one-shot private audio/token. `run` returns saved admission metadata/outcome through the existing retention boundary. Duplicate/terminal/blocked/foreign requests do not invoke another adapter. A pre-aborted request cancels before invocation. Before queued invocation it rechecks durable state and deadline; explicit processing consent and the exact language hint come from the admitted record, not a new caller grant. No retry, fallback, new unit charge or automatic restart execution is added.

Execution waits only until the durable claim deadline, clamped to role/media/session expiry, or cooperative parent/cancel abort. A timeout/abort response **does not prove work stopped**. If an adapter ignores its signal, `run` returns pending metadata while the owner slot remains held until the actual invocation promise acknowledges. Late text is discarded; settlement receives only the already-selected fixed failure. Existing settlement also rechecks consent/session/expiry and suppresses cancellation/revocation output. Forged, malformed, encoded-oversized or throwing provider results become `provider_failed`, without raw error retention.

`cancel(owner,id)` commits owned cancellation before signalling this coordinator's active invocation. Foreign cancellation cannot signal another owner. Direct store cancellation/revocation, or a different coordinator instance, has no shared in-process event bus; durable invalidation still suppresses output, but immediate cooperative signalling is not guaranteed. Cancellation cannot recall copied bytes or forcibly kill synchronous JavaScript. Live network transports are not registered.

Trusted `stop()` is terminal for this coordinator instance. It rejects subsequent run attempts before role lookup or private claim, including attempts to use run as a cached read; owned store status remains separately readable. It signals the currently registered jobs once and returns only `stopping`, `pendingWorkers` and `acknowledgementFailed`. It does not wait for acknowledgement, mutate admissions/cancel labels, refund units or close storage. Repeated calls return current counts. Counts cover this instance's unfinished local jobs, not all durable pending records, permissions or proof that it is safe to close. An acknowledgement failure can leave a durable slot held with pendingWorkers=0 and the failure flag true; drain still throws.

Stop before queued invocation prevents adapter handoff. Stop during/after adapter fulfillment but before settlement converts late completion to a fixed aborted failure, including if validation itself triggers stop. Already-settled evidence is preserved. Abort-ignoring work keeps its durable slot until the actual promise acknowledges; a stop never releases it early. Stop cannot forcibly interrupt synchronous code/abort listeners or restart another instance, and it is not persisted as global server policy. A future host must first stop admitting new requests, stop every relevant coordinator, and drain before closing storage. No bounded shutdown-wait/force-exit helper or public shutdown integration is added here.

Trusted `drain()` awaits a snapshot of active actual acknowledgements. It can wait indefinitely for an abort-ignoring adapter and is not a public response or background cleanup guarantee. A persistence failure yields a fixed503 from foreground execution/drain, prevents further runs in that coordinator, leaves the durable pending record for exclusive recovery, and never retries. Background acknowledgement rejections are consumed and surfaced through drain without raw errors/unhandled rejection. The store must stay open until acknowledgement/drain; on process loss the existing exclusive kernel-lock startup interrupts work, invalidates private tokens and never replays. Public shutdown/signal lifecycle integration remains pending.

Tests use fresh synthetic stores and real default fixtures in both providers/all three fixture locales. Abuse cases cover running/completed duplicates, owner isolation, immediate cancellation, parent abort, deadline and abort-ignoring acknowledgements, revoked late output, policy changes, forged/oversized/throwing results and acknowledgement storage failure. Lifecycle tests cover pre-claim/queued/in-flight/repeated stop, late completion during validation, preserved settled results and failure visibility. A real child process stops an abort-ignoring worker, retains its kernel/worker slot while alive, then is killed; exclusive restart interrupts it without replay or another ledger charge. No live provider call, paid inference, real recording, quality measurement, vendor key, public route, channel, booking or deployment is enabled.
