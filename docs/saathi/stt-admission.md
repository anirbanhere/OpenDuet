# Fixture STT admission reservations

Schema10 adds internal `SelfHostedStore.sttAdmissions`: `begin(owner,input,serverRole)`, `get(owner,id)` and repeat-safe `cancel(owner,id)`. A reservation is not a transcription, execution lease or completed task. No provider, raw audio, transcript, endpoint or background worker is returned or invoked. Live/disabled/unimplemented speech roles are refused; only the two reviewed synthetic STT fixture profiles can be pinned. Selecting a fixture role does not prove the input contains genuine speech or matches the fixture tone catalogue.

Input contains only `request_id`, owned `media_id` and exact `consent_revision`; owner/session and credential-free role come from the server. New reservations check current media consent, ownership, active session/storage, expiry, rounded duration and permitted hint. The strict role schema excludes credentials and arbitrary models. Exact duplicate requests return their saved state and immutable role even if current defaults change, without a new unit charge. Changed media/revision under the same ID conflicts409. The saved reservation is historical evidence, not fresh permission to process; later execution must recheck authoritative consent and current provider policy.

Immediate transactions and a partial unique index permit one pending **STT reservation** per owner, independently of the existing chat/planning guard. Defaults are20 global/4 owner admissions and300s global/60s owner audio units per UTC day; only tighter internal overrides are allowed. Lifetime5,000 global/100 owner ledger records bound growth. Rounded audio milliseconds are reserved before any execution. These counters are admission/unit limits, not actual provider calls or verified currency billing. Cancellation/restart do not refund units. The separate usage ledger survives removal of admission rows; future account erasure/aggregation and ledger retention need their own policy.

Reserved clips may expire; expiry does not run a worker or automatically free a pending reservation. The owner can cancel it. On exclusive full-store startup, leftover reservations become interrupted and duplicates never replay them. The existing kernel lock must establish that the previous full server is gone before recovery. There is no execution claim or active vendor to cancel in this increment, so cancelling a reservation can release its slot; this must change for in-flight execution before providers are connected.

Tests use fresh synthetic SQLite state, generated tone bytes and coordinated child processes. They cover ownership/consent/role boundaries, duplicates/pins, daily audio/admission and lifetime budgets, UTC rollover, rollback on ledger failure, migration preservation, pending races and restart/no replay. A legacy read-step migration test now preserves its injected clock on reopen, avoiding real-date-dependent fixture failures; production date policy was not weakened.

Schema9 migration preserves media consent/history and existing chat/inference usage. Development did not migrate public/private databases. Older schema7/8/9 binaries refuse10; do not launch this branch with an existing profile or deploy without a separately authorized consistent backup/upgrade. Before actual speech: one-shot claims, rechecks, revocation/cancellation/late settlement and restart handling, appropriate live-provider admission/cost policy and actual consented evaluation. Public voice/WhatsApp and real actions remain disabled.
